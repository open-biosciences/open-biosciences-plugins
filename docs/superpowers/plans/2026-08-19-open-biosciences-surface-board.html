The short answer

Plugins: yes, and ahead of the private relational plugin

open-biosciences-plugins is the pattern the private relational plugin is still trying to reach. It already has a valid .claude-plugin/marketplace.json listing two plugins, each with its own plugin.json, .mcp.json, CONNECTORS.md, commands/, skills/ and references/, plus two GitHub Actions workflows. Nothing structural is missing.

Workspace template: no — and there is direct evidence it is not trusted

biosciences-workspace-template has none of the five invariants the other two templates enforce, and it carries 72 tracked files of run output — 2.5 MB across 11 run directories, 7 of which its own README never mentions.

The proof is not the checklist, it is the behaviour: a private research instance was generated from a private workspace template instead. Its instantiation commit says why, in its own words — an earlier build was abandoned because generating from the predecessor "carried its committed run corpus into this history." That is precisely the defect the biosciences template still has.

Two things that look like defects and are not

~~literature, ~~data repository and friends read like broken markup. They are a documented convention: CONNECTORS.md defines ~~category as a placeholder so workflows stay tool-agnostic and any MCP server in that category works. Leave them alone.

The ob-* commands and biosciences-* skills are not duplicates of each other. Commands are thin orchestration entry points that name the skill they drive; the skills hold the procedure. 6 + 11 is the real surface.

One thing that looks fine and is not

biosciences-skills holds nine skills with the same names as the plugin's. All nine differ substantively — not whitespace. The plugin copies are newer, uniformly: 2026-03-06 against 2026-02-28. So this is a stale predecessor rather than a live parallel tree, and the fix is to archive or redirect it, not to build a drift gate.

But the drift is not purely additive. The plugin's biosciences-clinical dropped the block explaining when to use slim=true versus slim=false, which the older copy still carries — while ob-research.md still tells the user the pipeline handles slim automatically. Worth reading before deleting anything.

Gaps worth closing

Now

/start is referenced five times and does not exist

Two commands and one skill tell the user to run /start to check connectivity — ob-cq-run.md even aborts and suggests it. No start.md exists in either plugin. This is the same gap a private plugin's start skill was drafted to fill; the connectivity-probe half of that draft ports directly.

Now

Give biosciences-workspace-template the enforcement layer

Copy the shape from the private workspace template: .claude/rules/, scripts/check-layer.sh, .githooks/, .gitattributes, and an output/*/ ignore rule with the TEMPLATE-ONLY block instances delete on instantiation. Until then check-layer cannot run, so nothing stops the next instance inheriting the run corpus.

Now

Decide the fate of the 11 committed run directories

Four are cited by the README and can stay as worked examples if that is the intent — but then say so, in the README and in the layer rules, so check-layer can whitelist them rather than fail. The seven unreferenced ones, including qw, qw3 and qw4, belong in an instance.

Next

Split the three oversized skills

biosciences-cq-runner first at 909 lines. The plugin already has a references/ convention holding fuzzy-to-fact.md and token-budgeting.md — the phase tables and gold-standard comparisons are exactly what progressive disclosure is for.

Next

.gitattributes across the estate

13 of the 14 biosciences repos lack it. The one that has it — the private research instance — inherited it from the template it was generated from. The symptom is already visible: open-biosciences-plugins currently shows marketplace.json as modified when every line is byte-identical.

Then

Reconcile biosciences-skills with the plugin

Read the slim divergence first, port anything still true, then make the repo either a proxy tree or an archive. Nine forks with no generator is the failure mode the private plugin plan was written to avoid.
